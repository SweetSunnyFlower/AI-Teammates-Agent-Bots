# SMTP 邮件发送设计

- **状态：** 已确认，可进入实施计划
- **日期：** 2026-11-20
- **范围：** 使用自建 SMTP 配置让 Bot 发送纯文本邮件

## 目标

在 Bot 设置中新增可由任意角色自行勾选的“发送邮件”工具。只有勾选该工具的 Bot 才能使用
`send_email`。邮件通过配置的 SMTP 服务器发送，不依赖 Composio。

所有发送操作继续遵守 Dotty 的人工审批规则：聊天不能直接发信，后台任务必须先创建
“待我处理”审批卡，用户批准或编辑后才发送。

## 非目标

- 不读取、搜索或管理 QQ 收件箱。
- 不实现附件、HTML 正文、模板、定时发信或批量营销邮件。
- 不使用 Composio 的 Gmail/Outlook 工具替代本地 SMTP。
- 不自动重试发送，避免 SMTP 已在服务端接受后仍重复投递。

## 配置

必需环境变量：

```dotenv
SMTP_HOST=smtp.qq.com
SMTP_PORT=587
SMTP_USER=<mailbox address>
SMTP_PASS=<provider authorization code>
EMAIL_FROM=<mailbox address>
```

`EMAIL_FROM` 的地址部分必须与 `SMTP_USER` 相同。端口必须是 1–65535 的整数。465 端口使用
隐式 TLS；587 使用 STARTTLS。所有连接、握手和发送都有明确超时。

凭据只允许存在于服务端的 `.env.local` 或 systemd `EnvironmentFile` 中，不得进入客户端包、
日志、审批卡、异常消息或 Git。

## 组件

### SMTP 配置与发送器

独立的服务端模块负责：

1. 读取并校验 SMTP 环境变量。
2. 创建不带连接池的 Nodemailer transport。
3. 提供 `verify()` 用于验证登录和 TLS，不发送邮件。
4. 提供 `send()`，校验并规范化最终邮件参数后调用 SMTP。

SMTP transport 在模块内懒加载并复用配置，不跨不同环境变量热更新。修改配置后必须重启 Web
和 worker。

### AI 工具

工具目录新增：

```text
key:   email.send
label: 发送邮件
group: 沟通
gated: true
roles: head, lead, worker
```

所有角色都能在 Bot 设置中勾选，但不会自动启用任何 Bot。勾选后该 key 写入
`bots.tool_keys`。

AI 工具名为 `send_email`，输入参数：

| 字段 | 必填 | 规则 |
|---|---|---|
| `to` | 是 | 一个或多个逗号分隔的邮箱地址，最多 20 个 |
| `cc` | 否 | 一个或多个逗号分隔的邮箱地址，最多 20 个 |
| `bcc` | 否 | 一个或多个逗号分隔的邮箱地址，最多 20 个 |
| `subject` | 是 | 1–200 字符，不允许 CR/LF |
| `text` | 是 | 1–20,000 字符的纯文本正文 |

审批卡使用工具标识 `SMTP_SEND_EMAIL`，显示为“SMTP 邮箱 · 发送消息”，所有参数字段都可通过
现有编辑机制修改。

## 数据流

### 聊天

```text
用户提出发邮件
  → Bot 调用 send_email
  → 聊天环境没有审批处理器
  → 工具返回“需要创建后台任务”
  → Bot 使用 create_task 创建实际发送任务
```

聊天中不得声称邮件已发送。

### 后台运行

```text
worker 执行任务
  → Bot 调用 send_email
  → 生成 SMTP_SEND_EMAIL 审批请求
  → 写入 inbox_items 并等待用户决定
  → 用户批准或编辑
  → 重新校验最终参数
  → SMTP 发送
  → 返回 messageId 和 accepted 收件人
```

用户拒绝、审批超时或参数校验失败时，工具返回未发送结果，Bot 不得重试或绕过。

## 错误处理

- 配置缺失：返回明确的“SMTP 尚未配置”工具错误。
- 地址或主题非法：在审批前拒绝；用户编辑后再次校验。
- SMTP 认证、TLS、连接或超时错误：返回脱敏后的错误摘要。
- SMTP 拒绝全部收件人：视为发送失败。
- SMTP 接受至少一个收件人但拒绝其他收件人：结果标记为部分成功，并列出被拒绝地址。
- 发送结果不确定：不自动重试，要求用户检查已发送邮件。
- 异常信息必须移除 SMTP 密码和认证码。

## UI

在 Bot 设置的“工具”区域动态增加“沟通”分组，显示“发送邮件”复选框和现有的
“需要审批”标记。界面需要同时在普通视图和紧凑视图中保持复选框文字垂直居中。

## 测试

### 单元测试

- SMTP 配置缺失、端口非法、发件人与登录账户不一致。
- 邮箱地址解析、逗号分隔、数量上限和 CR/LF 注入。
- 主题和正文长度边界。
- 未勾选 `email.send` 时工具集合不包含 `send_email`。
- 聊天中没有审批处理器时不调用 SMTP。
- 审批拒绝或超时时不调用 SMTP。
- 审批编辑后的参数用于发送。
- SMTP 全成功、部分拒绝、全拒绝和异常结果。
- 错误文本不包含密码。

### 手工验证

1. 在 `.env.local` 写入 SMTP 配置但不输出密码。
2. 运行 `transporter.verify()` 脚本确认 QQ SMTP 登录和 TLS。
3. 在某个 Bot 设置中勾选“发送邮件”。
4. 从聊天创建发信任务。
5. 在“待我处理”编辑并批准。
6. 检查 QQ 已发送邮件和工具返回的 `messageId`。

## 验收标准

- 只有手动勾选“发送邮件”的 Bot 拥有 `send_email`。
- 聊天无法绕过审批直接发信。
- 批准前没有任何 SMTP 发送调用。
- 批准后的最终编辑内容与收到的邮件完全一致。
- 发送失败有可读、脱敏的错误，不自动重复发送。
- 现有 Composio、搜索、任务和审批流程不受影响。

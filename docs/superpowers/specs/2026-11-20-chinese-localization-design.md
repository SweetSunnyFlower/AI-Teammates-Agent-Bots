# Dotty 单中文汉化设计

- **状态：** 已由用户确认（2026-11-20）
- **范围：** 用户可见界面、AI 行为、渠道消息与用户文档
- **默认语言：** 简体中文

## 1. 目标

Dotty 保持单语言运行，不增加语言切换或本地化路由。首次打开页面时，所有产品界面、
系统反馈、AI 对话和安装文档均使用简体中文。

汉化需要让用户能够不依赖英文完成以下核心流程：

1. 注册、登录和创建工作空间。
2. 浏览 3D 办公室、部门和 Bot 状态。
3. 私聊 Bot，由总控 Bot 规划并分派任务。
4. 使用任务看板、任务详情、待我处理和审批。
5. 管理 Bot、部门、例行任务、连接器和设置。
6. 查看活动、任务结果、错误信息和通知。
7. 按照 README 从零启动和部署项目。

## 2. 设计选择

采用**单中文直接替换**：产品只提供简体中文，不引入 `[lang]` 动态路由、`next-intl`、
语言字典文件或语言切换器。

没有采用完整双语 i18n，因为当前需求不需要英文界面，多语言路由会增加页面结构、
服务端参数传递和测试成本。没有采用“只汉化界面”，因为用户已明确要求 AI 提示词和
文档一起汉化。

## 3. 范围

### 3.1 界面

- 页面标题、页面正文、导航、按钮、标签、表单字段和占位符。
- 3D 办公室中的楼层面板、Bot 列表、状态标签、活动和空状态。
- 聊天抽屉、消息状态、工具调用提示、审批卡片和问题卡片。
- 任务看板、任务详情、运行记录、时间与金额说明。
- 设置、连接器、频道、工作空间、Bot、部门和例行任务对话框。
- Toast、确认框、校验错误、服务端 Action 错误和用户可恢复错误。
- 加载、禁用、空数据、超时、离线、权限不足和会话过期提示。
- `aria-label`、屏幕阅读器文本、Tooltip、页面 metadata 和错误页。
- `<html lang="zh-CN">` 和中文页面标题。

用户自行创建的 Bot 名称、工作空间名称、任务标题和消息内容不翻译。

### 3.2 AI 行为

- 系统提示词、任务提示词和工具描述改为中文。
- 工具返回给模型的用户可读错误改为中文；外部 API 原始错误可保留英文并以中文说明。
- Bot 默认使用简体中文回复。
- 如果用户明确要求英文或其他语言，Bot 应遵循用户当次要求。
- 任务汇报、审批理由、超时说明、交接说明和后台运行结果使用中文。
- Telegram 与 Slack 的按钮、状态、审批卡片、问题卡片和欢迎消息使用中文。
- 代码、命令、仓库名、分支名、API 字段和错误码保持原样。

### 3.3 文档

- `README.md` 全文中文化。
- `deploy/README.md` 全文中文化。
- `.env.example` 的说明注释中文化，环境变量名和示例值保持原样。
- 面向用户的启动、测试、部署和故障排查命令保持可复制执行。

## 4. 保持英文的内容

以下内容不是用户界面文案，翻译会破坏兼容性或增加维护成本，因此保持不变：

- 数据库枚举、任务状态值、API JSON 字段和数据库列名。
- TypeScript 标识符、路由、环境变量名和文件名。
- 内部日志、开发调试信息、代码注释和第三方库原始错误。
- `DESIGN.md`、实施计划和其他面向维护者的架构文档。
- GitHub、Slack、Telegram、SearXNG、DeepSeek、Podman、Docker、Caddy、PostgreSQL、
  OAuth、API、Token 等产品名或技术名。
- 用户已经存在的英文数据。

## 5. 术语

同一概念在所有界面和 AI 文案中使用同一译名：

| 英文 | 中文 |
|---|---|
| Workspace | 工作空间 |
| Office | 办公室 |
| Floor | 楼层 |
| Department | 部门 |
| Head bot | 总控 Bot |
| Lead bot | 主管 Bot |
| Worker bot | 执行 Bot |
| Waiting on me | 待我处理 |
| Board | 任务看板 |
| Task | 任务 |
| Activity | 动态 |
| Routine | 例行任务 |
| Connector | 连接器 |
| Channel | 渠道 |
| Approval | 审批 |
| Run | 运行 |
| Resting | 休息中 |
| Working | 工作中 |
| Waiting | 等待中 |
| Error | 出错 |
| Done | 已完成 |

技术专有名词保留英文，例如 `PostgreSQL`、`GitHub App`、`DeepSeek API Key`。

## 6. 文案风格

- 使用简洁、自然、友好的简体中文。
- 按钮使用动作短语，例如“创建工作空间”“添加 Bot”“保存”“重试”。
- 错误说明先说明发生了什么，再给出下一步，例如“连接失败，请稍后重试。”
- 不使用生硬直译，不把内部实现细节暴露给用户。
- 中文标点使用全角标点；代码、命令、URL 和环境变量名保持原样。
- 英文按钮中已有的紧凑布局需要检查换行和截断，避免中文变长后溢出。

## 7. 实施边界

- 不改变数据模型、认证流程、任务执行逻辑或权限规则。
- 不重做布局；只为中文长度做必要的宽度、换行和截断调整。
- 不翻译第三方服务自身返回的内容。
- 不翻译用户数据。
- 不在本次改动中增加新的业务功能。

## 8. 验证

实现完成后需要验证：

1. `npm run build` 成功。
2. `npx tsc --noEmit` 成功。
3. `npm test` 全部通过。
4. `npm run lint` 为 0 error。
5. 扫描 `app/`、`components/`、`lib/`、`jobs/` 和 `scripts/` 中仍直接展示的英文界面文案。
6. 浏览器逐项检查落地页、登录页、创建工作空间、办公室、聊天、看板、待我处理、
   例行任务、设置和错误页。
7. 检查 375px、768px、1024px 和桌面宽度下没有明显文字溢出或遮挡。
8. 发送中文任务，确认 Bot 默认用中文回复；明确要求英文时，确认 Bot 可以切换。

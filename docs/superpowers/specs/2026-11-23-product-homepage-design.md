# Dotty 产品首页设计

- **状态：** 已由用户确认并实现（2026-11-23）
- **范围：** `/` 访客产品首页
- **选定方向：** 产品现场手册
- **目标用户：** 希望让 AI 真正执行多步骤工作的个人用户和自托管用户

## 1. 目标

现有首页只有居中的一句主张和两个按钮，用户看不到产品界面，也不知道 Dotty 与普通
AI 聊天工具有什么区别。首页需要完成四件事：

1. 在三秒内说明 Dotty 是什么。
2. 用真实办公室界面证明这不是一个套壳聊天页面。
3. 解释任务如何从一句话变成一组有审批边界的结果。
4. 把访问者引导至注册登录或工作空间入口。

首页不虚构客户、评价、节省比例或效率数字。没有真实材料的内容不进入页面。

## 2. 叙事与信息架构

页面采用“产品现场手册”的阅读顺序，而不是通用 SaaS 的卡片瀑布。

### 2.1 顶部导航

- 左侧：`Dotty` 文字标识和一个小型产品状态点。
- 中间锚点：`工作方式`、`产品能力`、`安全边界`、`自托管`。
- 右侧主操作：`开始使用`，进入 `/auth/login`。
- 移动端隐藏中间锚点，只保留文字标识和主操作。

### 2.2 首屏

左侧是产品主张，右侧是真实办公室截图。

- 眉题：`自托管 AI 团队 · 现场手册 01`
- 主标题：`把工作交给一支 AI 团队。你只负责最后点头。`
- 说明：说明总控 Bot 负责规划、部门负责执行，发送、支付、发布、删除和合并必须审批。
- 主按钮：`开始组建团队`，进入 `/auth/login`。
- 次按钮：`看看办公室`，进入 `/workspace`。
- 辅助说明：`邮箱密码登录 · 数据保存在你的 PostgreSQL · DeepSeek 提供模型能力`。
- 右侧：用真实 `dotty-home.png` 制作浏览器窗口式产品展示，轻微倾斜和纸张阴影。
- 截图旁只使用产品已有的概念标签，不添加虚假的在线人数或运行统计。

首屏下方放一条紧凑能力带：

`总控分派`、`部门协作`、`审批闸门`、`例行任务`、`自托管`、`DeepSeek`

### 2.3 工作方式

标题：`一句话进来，一组结果出去。`

四个连续步骤：

1. **交办**：把目标告诉总控 Bot。
2. **拆解**：总控按部门拆分任务并指派给 Bot。
3. **执行**：各楼层并行工作，办公室实时显示状态。
4. **审阅**：外向动作停在“待我处理”，批准后才执行。

桌面端横向排列，步骤之间用硬边连接线；移动端改为纵向时间线。

### 2.4 产品能力

标题：`不是一个聊天框，而是一间会工作的办公室。`

使用四张不同大小的编辑式卡片：

- **总控与分派**：总控 Bot 规划工作，Lead Bot 和 Worker Bot 在楼层间协作。
- **看得见的进度**：工作中、等待中、休息中和出错状态映射到 Bot、楼层和活动流。
- **例行任务与晨间回顾**：按计划启动工作，把夜间完成、失败和待审批事项汇总。
- **研究、邮件与工程**：SearXNG 搜索、SMTP 邮件和容器化代码执行按 Bot 授权启用。

卡片使用真实产品截图、图标和简短说明，不放泛化营销文案。

### 2.5 安全边界

标题：`自动化可以很快，但最后一步必须是你。`

页面明确列出五类审批动作：

`发送`、`支付`、`发布`、`删除`、`合并`

右侧展示一张静态“待我处理”审批示例，说明：

- Bot 准备执行的动作。
- 用户可以批准、编辑或拒绝。
- 未获批准时工具不会执行。

审批示例必须标注为“示例”，不能伪装成真实用户数据。

### 2.6 自托管

标题：`你的团队，运行在你的服务器上。`

说明 Dotty 不依赖 Supabase、Trigger.dev 或 Upstash Box。页面用技术标签展示实际运行栈：

`Next.js`、`PostgreSQL`、`Better Auth`、`pg-boss`、`DeepSeek`、`SearXNG`、
`Docker / rootless Podman`、`Caddy`

不突出部署命令，不把首页变成架构文档。详细架构留给 README 和架构图。

### 2.7 结尾行动区

标题：`先给它们一件小事。`

说明用户可以创建第一个工作空间并把首个任务交给总控 Bot。

按钮：

- `开始使用`，进入 `/auth/login`。
- `看看工作方式`，跳转到同页的工作方式章节。

### 2.8 页脚

- 左侧：`Dotty` 和 `用一间办公室组织 AI 工作。`
- 右侧：`产品`、`工作方式`、`安全边界`、`开始使用`。
- 底部：当前年份和 `自托管 · 简体中文`。

## 3. 视觉系统

### 3.1 设计锚点

延续现有 Dotty 现场笔记和暖色玩具办公室，不改成普通深色 AI 官网。

- 视觉温度：温暖、可信、略带游戏感。
- 观看距离：桌面一米以内，移动端近距离。
- 叙事角色：访客首屏到最终转化。
- 容量：七个内容区，桌面端依靠大留白和编辑式排版保持呼吸感。

### 3.2 颜色

只使用现有系统色和由这些颜色派生的透明色：

| 用途 | 色值 |
|---|---|
| 纸张背景 | `#E3DCCB` |
| 明亮纸面 | `#FBF7F0` |
| 面板 | `#F4EEE3` |
| 下沉面板 | `#EBE3D4` |
| 暖墨 | `#2B2620` |
| 次要文字 | `#7D7468` |
| 草地绿 | `#8CC15D` |
| 蜂蜜黄 | `#F0DAB1` |
| 夜色蓝 | `#20263D` |
| 危险/等待强调 | `#C16565`、`#D49A52` |

不使用紫色渐变、蓝紫霓虹、纯白 SaaS 背景或额外品牌色。

### 3.3 字体

- 标题和正文：Nunito Sans，中文回退到苹方/微软雅黑。
- 眉题、编号、技术标签：Courier Prime。
- 标题使用高字重和紧凑字距，正文保持 1.6 左右行高。
- 主标题桌面端使用 `clamp()`，最大不超过 82px；移动端不小于 42px。

### 3.4 形状与层次

- 主要面板：14–20px 圆角、1.5–2px 暖墨描边。
- 按下按钮使用硬质底部阴影，不使用高模糊浮层。
- 纸张使用低对比点阵和轻微径向高光。
- 产品截图放在有浏览器顶部栏和硬阴影的窗口中。
- 卡片可以大小不同，但所有边缘遵循 4px 间距网格。

### 3.5 动效

- 首屏文案和截图使用一次 500–700ms 的轻微上浮和淡入。
- 卡片 hover 上移 2px，阴影增加 1px。
- 只使用 CSS，不引入动画库。
- `prefers-reduced-motion: reduce` 时关闭所有位移和循环动画。

## 4. 响应式与布局

### 4.1 桌面端

- 内容最大宽度 1280px，左右安全边距至少 32px。
- 首屏为 5/7 分栏：文案较窄，截图占主视觉。
- 工作方式和产品能力可使用 12 栏编辑式网格。
- 页面底部保持足够留白，避免最后一张卡片贴住页脚。

### 4.2 平板端

- 首屏改为上下布局，截图在标题和按钮下方。
- 四个步骤改为 2×2。
- 能力卡片改为两列，不保持复杂错落布局。

### 4.3 移动端

- 页面左右边距 20px。
- 导航只保留品牌和 `开始使用`。
- 按钮在空间不足时纵向排列，触控高度不小于 44px。
- 产品截图保持 16:9，不裁掉关键办公室内容。
- 审批示例和步骤全部改为单列。

## 5. 技术设计

- `/` 保持 Server Component，不增加 `use client`。
- 页面内容是静态常量，不需要数据库、认证状态或网络请求。
- 使用 `next/link` 处理站内导航。
- 使用 `next/image` 显示真实产品截图，并设置明确宽高避免布局跳动。
- 将 `_design/dotty-home.png` 复制到 `public/` 作为稳定生产资源，不直接从 `_design/` 提供服务。
- 页面 sections 使用语义化 `header`、`main`、`section`、`footer`。
- 如果页面文件过大，拆分为 `components/landing/` 下的纯展示组件；不引入客户端状态。
- 只在落地页需要时添加 CSS；复用现有颜色、边框和字体变量。

## 6. 可访问性

- 所有正文和背景对比度达到 WCAG AA。
- 所有锚点和按钮有可见 focus ring。
- 图标不单独承担语义，重要图标旁必须有文字。
- 产品截图有描述性 `alt`，装饰图形使用空 `alt` 或 `aria-hidden`。
- 页面只保留一个 `h1`，章节标题按层级使用 `h2`、`h3`。
- 锚点跳转目标设置 `scroll-margin-top`，避免被导航遮挡。
- 不用颜色单独传达状态，审批状态同时有文字。

## 7. 不包含

- 不在首页加载 React Three Fiber 或实时办公室。
- 不修改认证、工作空间、任务、Bot、审批或数据库逻辑。
- 不虚构客户 Logo、用户评价、运行数量或节省比例。
- 不增加价格页、博客、帮助中心或语言切换。
- 不新增依赖。

## 8. 验收标准

1. 访客无需登录即可看到完整产品主张、产品截图和主要能力。
2. 首屏主按钮进入 `/auth/login`，次按钮进入 `/workspace`。
3. 页内锚点可到达工作方式、产品能力、安全边界和自托管区。
4. 375px、768px、1024px、1440px 宽度下没有横向滚动、文字截断或重叠。
5. 页面在移动端首屏之后有清晰、连续的阅读节奏。
6. 浏览器 console 无 error 和 warning。
7. `npm run lint`、`npx tsc --noEmit`、`npm run build` 成功。
8. `/` 在构建输出中保持静态或可预渲染，不因首页改动引入数据库依赖。
9. reduced-motion 下不出现持续动画。
10. 首页截图与实现后的浏览器截图完成桌面和移动端视觉核对。
